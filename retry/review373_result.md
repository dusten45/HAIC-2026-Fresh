# 373 기존 TRAIN·오래된 DEV의 개선 기회와 중복 검토

**365는 탈락으로 고정하고 champion 296을 유지한다. 새 정책 규칙의 우월성은 찾지 못했지만, 기존 334의 “H1 OFF·fallback ON·birth-routing OFF” 구성은 실제 폐루프가 미측정인 빈칸으로 남아 있다.** 단순히 미시도 조합이라서 추천하는 것은 아니다. 이 구성에는 오래된 296 TRAIN에서의 운동 관측 오차 감소와 접촉 전 제어 노출 근거가 있다. 완주 개선은 아직 입증되지 않았다.

이번에는 새 환경·시뮬레이션·actor·routing·모델 호출·학습·후보 생성·예산 배정·예약을 모두 하지 않았다. 372는 부모가 전달한 **후보 탈락 결정만** 반영했다. 372의 개별 조건·결과·궤적과 297 조건 파일을 다시 읽거나 설계에 사용하지 않았다. 기존 TRAIN과 오래된 DEV 보고서·저장 출력·334~371 실행 메타데이터만 대조했다.

따라서 네 요소가 전혀 분리되지 않았다는 진단은 맞지 않는다. 반대로 완전한 factorial 실제 주행을 마쳤다고 말할 수도 없다. 모든 미측정 조합을 채우는 실험군이나 H1·filter의 새 threshold sweep은 제안하지 않는다. **이득이 남는 최소 구성을 이미 확보했다는 결론도 아니다.**

334의 네 artifact는 여전히 존재하며 H1 활성 여부는 동결된 모델 모듈의 ENABLED, fallback은 temporal 모듈의 해시로 구분했다. H0/F1의 기존 ZIP은 `7da9a3dc5c6aa65b791fd96b5e58203cfb5a3192f99efccb7cbc9082b278f46f`이다. H1 비활성 wrapper와 기존 자산은 남아 있지만 선택은 disabled여서 기능상 296+fallback이고, 새 모델·새 공식·birth-routing/history는 없다. 더 작은 ZIP을 새로 만들지는 않았다.

334~371의 readiness 메타데이터 **89개**를 확인했다. 정확한 로드 모듈 조합이 맞는 기록은 13개이며 H0/F1 실제 sibling 결과는 0이다. 오래된 worker가 ready 파일을 저장하지 않은 경우를 놓치지 않도록 **36개 계획**의 구성도 추가 대조했다. 334의 캐시 구성 외에 H0/F1 등록은 없고 335·336·337은 H1/F1이었다. 파일명이나 ZIP 재압축 hash만으로 중복을 판정하지 않았다. 이 유한한 범위 밖 모든 과거 변형의 부재를 증명한 것은 아니다.

334에서 **이미 계산·저장된** OFF/ON JSON을 산술 비교했다. actor나 detector를 다시 호출하지 않았다. 전체 제어 차이는 542/1,754입력이고 조향 차이는 378개다. 아래는 순차 고정 픽셀 replay의 기존 출력이다.

T2950에서는 첫 전체 제어 차이 28과 경로·조향 차이 149가 기존 접촉 184보다 앞선다. 따라서 305처럼 첫 충돌이 난 뒤에야 작동하는 경로 복구와는 다르다. 그러나 바뀐 명령을 실제로 실행한 궤적은 아니다. ON은 자신의 명목 조향 기억을 갱신했지만 영상과 물리 명령 이력은 기존 296 기록이며, 실제 새 branch 시점이나 완주·접촉 결과를 예측한 것으로 쓰지 않는다. 특정 행동 149나 184를 새 정책의 runtime 조건으로 넣지 않는다.

작동 가설은 **현재 296에서 optical을 사용할 수 없는 구간의 retained 장애물을 회전 없이 전방 이동만 하면 현재 차량 좌표의 방향이 틀어질 수 있고, 기존 고정 HUD 회전 fallback이 그 오차를 줄일 수 있다**는 것이다. 334의 출생 fixture 대응 subset에서 single-interval 도로 균등 평균 오차는 4.640→2.752m, 각 여섯 도로 평균은 모두 감소했다. 반면 미해결 검출을 포함한 최근접 순차 평균은 24.400→25.294m로 악화했고 가림 보존은 미검증이었다. 좋은 subset만으로 전체 tracker 개선이나 충돌 회피를 보증하지 않는다.

정책의 정보는 현재·직전 픽셀의 기존 HUD yaw/speed, 원래 tracker와 정상 기억뿐이다. 식은 334 그대로 `Δψ=.08×(이전 yaw+현재 yaw)/2`, `p_next=R(-Δψ)(p_old−(0,현재 HUD speed×.08))`다. 승인 optical·검출·age·dedup·expiry·원래 routing·head·controller·lookahead·계수는 유지한다. GT pose·진행률·fixture·reward·372 조건 식별자·미래 영상은 정책 입력에 사용하지 않는다. norm speed를 정확한 전방 속도라고 보지 않으며 횡이동·충돌 후 slip과 숨은 운동 오차는 남는다.

**가장 작은 후속 반증은 제안만 남긴다. 실행·예약은 없다.** 기존 H0/F1/R0 ZIP을 한 개로 동결한 T2950 단일 에피소드, 새 reset 1회, 최대 **2,000 wrapper 행동**이다. 실제 raw step 최대8,000 + reset51 tick이며 별도 학습·source rollout·유료 자원·추가 배정·예비 사용은 0이다. 최악 사용 후 연구 잔액은 39,600회지만 이번 잔액은 그대로다. 기존 자격 있는 296의 T2950 315행동/DNF를 역사적 대조로 사용하므로 새 causal paired 실험이라고 부르지 않는다. 같은 full RNG/정책 상태 접두를 증명한 과거 대조도 아니다.

새 초기 상태까지 맞춘 causal pair가 필요하면 **A296+B를 합계 최대4,000행동·reset2회로 대체 등록**해야 한다. 2,000 실행 뒤 결과에 따라 A를 덧붙이는 방식은 제안하지 않는다. 재현 자료가 부족하면 개봉·주행 전에 멈춘다.

실행 전에는 기존 TRAIN case/초기 영상·등록 기하·장애물 신원, ZIP/member/model·worker·환경·런타임·입력 제한, H1 비활성·birth-routing/history 부재와 승인 optical 보존을 확정해야 한다. 자기 관측·반환 전체 제어·정상 기억을 사용하고 첫 공식 완주/은퇴, 2,000 상한, 승인 종료 시각, 기술·합법성·무결성·알려진 지원점 누락 중 먼저 도달하면 멈춘다. 상한은 protocol censor이며 DNF로 바꾸지 않는다. 재시도·조건 대체·cap 연장·threshold 수정은 없다.

T2950이 공식 완주하지 못하면 이 단순 구성의 **국소 구제 충분성**을 기각한다. 완주해도 작은 feasibility만 통과하며 승격·전체 TRAIN·DEV·HOLDOUT·SEALED로 자동 진행하지 않는다. 별도의 T2954 회귀 계약을 승인받는다면 최대2,000행동, 기존296 27.440초 공식 완주와 비교해 완주 보존을 먼저 확인할 수 있다. T2950 구제와 T2954 보존 둘 다 있어야 다음 넓은 TRAIN 계약을 검토할 최소 근거다. 현재는 어느 이득도 새로 측정하지 않았다.

독립적인 다음 작업으로는 **정책 모듈 조합·실제 주행/고정 픽셀 replay·조건·비용을 연결한 단일 색인**이 유용하다. 이번처럼 ready 파일 부재를 미실행으로 오해하지 않도록 계획·native 결과를 함께 연결한다. 또한 기존 368의 상태 캡처158.692초와 simulation/render158.397초처럼 평가 관측 비용이 크므로, 저장 TRAIN에서 요약 산출 중복을 줄이는 작업은 후보 튜닝 없이 가능하다. 초기 물리·RNG·raw 접촉·지원점 게이트의 근거를 삭제하거나 336에서 이미 고친 serializer를 새 연구 성과로 다시 세지 않는다. 새 정책 가설의 성공을 얻었다고 주장하는 대안은 아니다.

373의 신규 native·actor·환경 reset·routing·모델·학습·source rollout·유료 자원은 **모두0**이다. 첫 메타데이터·저장 JSON 감사 wall/CPU는 0.381/0.273초, 추가 계획 구성 감사는 0.017/0.011초다. 코딩·검토·보고·git 전체 시간은 아니며 실행 전 문법 검사 오류는 원장이나 호출 이전에 바로 고쳤다. 연구 **41,600회**, 예비 **84,000회**, 누적 wrapper **1,306,464회**, 운영 상한 **1,432,064회**를 v391에 보존했다.
