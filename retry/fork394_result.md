## 동결과 fork 자격

실행 전에 상태·arm·순서·원래 prefix·float32 명령·자격/중단 기준·원본 소스와 자료 hash를 동결했다. 한 arm마다 별도 reset부터 원래265의 동일 AST 제어식을 실행했다. N1은 O→C, O0는 O→H→C 순서이며 두 case는 독립 프로세스로 병렬 실행했다. 최대985 wrapper회·reset5회·CPU120초·wall300초·병렬2개를 지켰다. 각 process에 CPU soft59/hard60초와 별도 사전 timeout을 뒀고 공유 원장에서도 CPU/wall/native를 확인했다.

O는 원래 cursor의 `f+1.5(r-v)`, H는 같은 cursor의 `f*(sigma/r)+1.5(r-v)`, C는 실제 같은 사영점에서 읽은 `r,f,sigma`를 쓰는 식이다. 원래 clamp·페달 환산과 조향은 유지했다. N1에서 P=O, H=C인 동일 요청 arm은393의 사전 기준대로 중복 실행하지 않았다. 변경 명령은 각 prefix 끝의 한 행동에만 적용했다. 이후 행동이나 새 lap은 실행하지 않았다.

각 arm의 초기 상태와 fork 직전 **전체 이용 가능한 source 캡처·RNG·관측 hash·controller 기억**이 같은 case의 O와 정확히 일치했다. 캡처는 hull·바퀴 body/actuator/joint·도로 방문 상태/geometry·장애물·접촉·world flag·손상뿐 아니라 finish tracker와 wrapper raw counter를 포함했다. controller의 계산 전후 index/laststeer와 원래 명령도 비교했다. fresh reset과 실제 prefix를 사용했으며 source 복원 모델로 상태를 복사하지 않았다. 내보내지 않는 Box2D 내부 warm-start/manifold까지 직접 비교했다는 주장은 하지 않는다.

원래 nominal 계산은985행 모두 저장 명령과 같았다. 실제로 원래 명령을 적용한 prefix 및 O fork **982행**은390과 실제 pre/post 센서·접촉·손상까지 일치했다. 다른 명령을 적용한 행은 N1-C, O0-H, O0-C의 **3행**뿐이다. 5개 fork의 조향은 원래 float32 조향과 같았다. actor·teacher·학습·모델 적분은0이다. GT 상태와 고정 전체 경로/profile을 쓰는 진단이며 합법 픽셀 정책의 성능으로 세지 않는다.
