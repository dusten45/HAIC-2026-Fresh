## 동결과 자신의 상태를 사용한 제어

실행 전에 두 상태와 창, O→C 순서, 고정 경로·profile·gain, 자격·정보 게이트·중단·비용을 source hash와 함께 등록했다. 상한은808 wrapper회·reset4회·CPU120초·wall300초·병렬2개였고 actor·모델 적분·학습·예비 사용은0이다. N1/O0 case만 독립 프로세스로 병렬화했다.

각 arm은 reset부터 원래265 prefix를 재생했다. 초기와 첫 window 행동의 전체 이용 가능한 물리 캡처·RNG·관측 hash·controller 기억이 paired O 및394의 O와 정확히 같았다. 원래 행동을 실제로 적용한784행은 이전 기록과 pre/post 상태·접촉·손상까지 일치했다. C의24개 window 행동은 자신의 실제 상태로 계산했다. 네 window의 첫 행동과 전체 post 캡처도394의 해당 arm과 일치했다. 이는 같은 시작점의 연속 증거이며 새로운 독립 조건 검증은 아니다.

창 안에서는 O와C 모두 **자신의 실제 위치·속도로 원래 GT 조향 법칙과 index/laststeer를 갱신**했다. O는 원래 페달, C는 실제 같은 사영점의 `r,f,sigma`에서 계산한 페달을 사용했다. 저장된 미래 상태나 조향을 강제하지 않았다. 실제 조향 명령은 두 case 모두 첫 행동 이후11행동에서 O와C가 달랐다. 전체 지도·실제 상태를 쓰는 GT 진단이며 픽셀 정책 입력 자격은 여전히 별도다.

C는 유일한 내부 사영·양의 목표·음수가 아닌 진행률에서만 계산하도록 했다. 창 안의 목표0·비유일/끝점 사영·원래 cursor의 lap 분기·실제 arc 영역 이탈은 fallback 없이 중단하도록 등록했다. prefix의 원래 출발 제어를 바꾼 것은 아니다. 기술·정의역·CPU/wall 중단은 없었고 모든 실제 호출이 확인됐다. 내보내지 않는 Box2D 내부 warm-start까지 직접 비교했다고 주장하지 않는다.
