# Frozen policy route reproduction

`full_route_reproduction.py` performs one charged episode of an unchanged pixel-only package. Before running, a private plan freezes the package, simulator, observer, saved reference, action cap, time window and stop rules. There is no automatic retry. The observer hooks the original detector, tracker, ridge, route, target and controller calls, returns their original results and checks that each original decision call occurred exactly once. It records the full selected route, current detections, tracker memory and the actual fallback branch. A no-route fallback has an empty path, retains previous steering and brakes; an alternative path is not inferred.

The evaluator checks the reset observation and legacy pose, every full four-frame observation hash, float32 action bytes before stepping, post-step pose and endpoint flags. The first difference stops the episode and blocks diagnosis. The policy runs in a separate CPU process with only pixels and reset/act operations as inputs. The existing whole-call supervisor enforces import, reset and action deadlines, a decimal address-space/RSS ceiling and confirmed child reaping. Telemetry serialization and IPC are included in the action deadline. A resource failure also blocks diagnosis.

Both `ridge_path` centerline and selected route use hull-local metres: x right, y forward. The pixel conversion has already happened inside `ridge_path`; the recorded centerline must not be converted again. The evaluator records world pose, actual hull and wheel fixture geometry, fixture skin radii, obstacle circles and time before/after each decision. It wraps each existing raw simulator step once, records its pre/post state and first-contact flags, and returns the original result. Those privileged records are diagnosis inputs only and never enter the policy process.

After exact reproduction passes, following error is measured from the post-action vehicle position to the preceding decision's selected path transported into world coordinates. Replanned paths begin at the current origin, so distance to the new path would erase the error being measured. Missing routes are unknown/fallback rather than zero error. Persistent lateral and heading markers and no-new-tile markers are fixed before execution. Motion during a no-new-tile interval distinguishes stationary translation from moving without unique coverage; rotation is reported separately. The wrapper's off-track counter is a negative-reward streak, not a physical road-membership measurement.

Route clearance against policy estimates and physical obstacles is reported separately, with the origin-to-first-grid connector distinguished from grid segments. The routing margin is a radial proxy; physical hull/wheel polygon clearance uses the recorded geometry. Neither geometric clearance nor temporal ordering establishes dynamic feasibility or causality. One reproduced development failure does not identify failure rates or effects on other cases. The raw episode, case identities, plan, hashes and numeric diagnostics remain private; the public repository contains only generic tooling and qualitative findings.

In the admitted development reproduction, every selected path was present and the fallback was unused. The persistent lateral marker was absent. A persistent heading marker and the final no-new-tile run began before the first contact; the no-new-tile marker's required confirmation occurred after contact. That run included translation followed by stationary windows. Grid segments respected the policy's own hazard inflation, while the origin connector later violated the same constraint. Physical-obstacle radial proxies differed from perceived-obstacle proxies. Actual contact was consistent with hull fixture skin despite a positive vertices-only gap. These observations identify a connector safety-contract defect and coexisting direction/progress symptoms, without identifying a single cause of failure.

The one proposed future falsification holds perception, memory, speed and following fixed, rejects only a selected origin connector that violates the existing policy hazard margin, and uses the existing no-route fallback. Contact, stagnation and official completion would be reported separately: removing contact while retaining stagnation or failure would refute the claim that this connector defect alone explains completion failure. This intervention was not run and no automatic follow-up is scheduled.
