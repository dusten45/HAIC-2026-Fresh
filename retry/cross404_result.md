# 404 — 동결268 profile과 O/C 실행기의 실제 교차 비교

**새 O+268이14.78초를 실제로 재현했고, 같은 profile의 C는103행동에서 안전 중단됐다.** 기본 pace1.0에서는 O15.88초(이번 새 주행), C15.56초(402 재사용)였다. 따라서 C가 언제나 느리다거나268 profile이 경로에서 불가능하다고 결론 내릴 수 없다. 대신 **profile과 실행기의 결합에 따라 안전한 완주가 달라진다**는 실제 증거가 생겼다. C+268의 lap은 없으므로 네 칸의 수치 시간 상호작용은 계산하지 않았다. [집계 결과](cross404_result.json)

## 최소 구성과 선행 자격

새 주행은 O+base, O+268, C+268 세 개를 각각 한 번만 등록했다. C+base는402의195행동·15.56초 실제 기록을 명시적으로 재사용했다. 이 anchor는 새 주행이 아니며, current adapter가 저장된 실제 입력에서195개 명령을 정확히 재계산하는지 정적으로 확인했다. 세 새 주행의 초기 전체 이용 가능 물리·RNG·픽셀·도로는 이 anchor와 정확히 같았다. 반복된 알려진 N1이고 독립 일반화 표본은 아니다.

실행 전에1600 wrapper/reset3·CPU180초·wall300초·동시 worker1·예비 사용0을 동결했다. 최근402의22.138CPU초/294행동을1600회로 환산한 약120.5초에 계측·캡처 여유를 더했다. O+base600, O+268/C+268 각500행동 상한이었다. 기존3m 최근접 경로 오차·새 충돌/손상·도로 접촉 상실/잔디·의미 있는 후진 기준을 유지했다. 안전/도메인은 case 중단, shared 기술/source/자원/기한은 이후 주행 전체 중단이다. 원래 공식 중앙 통과 timestamp와 전방 끝 통과 완료로만 lap을 판정했다.

동결268 coefficient 파일·profile 함수의 hash와 과거269 등록값을 확인했다. 새 coefficient·배율·gain·경로 탐색은0이다. 재생성한 노드는 유한하며 시작0·나머지 양수, multiplier의 양 끝은 같은 주기 값이었다. C+268은 저장402의195개 현재 입력에서 유한한 제어와194개 양의 FIRST_LAP 목표를 냈다. 합성 현재 결승 후보의 양의 종단/0 기울기·공식 DONE·별도 STOP도 통과했다. 이는 정적 정의역·경계 자격이며 새 물리 예측은 아니다. [자격 코드](cross404_qualify.py)

O는 기존269의 제어 AST를 그대로 썼고, 원래 cursor와 첫 lap 이후 curvature profile 교체도 보존했다. C는 같은 nominal pursuit/출발 명령을 사용하되 실제 사영 arc와 시간 영역 진행률 보정·현재 공식 결승 metadata를 쓰는397 실행기다. 따라서 **전체 실행기 변형**의 비교이며 순수 gain 하나의 효과로 부르지 않는다. 공식 파일과 이전 실행기는 수정하지 않았다. [공통 adapter](cross404_common.py) · [실제 실행](cross404_run.py)

## 참조 profile 시간과 실제 시간은 다르다

| profile | 저장 노드의 이상적 참조 시계 | O 실제−참조 | C 실제−참조 |
|---|---:|---:|---:|
| base |15.3167초 |+0.5633초 |+0.2433초(402) |
| frozen268 |10.0272초 |+4.7528초 |미측정: 안전 검열 |

시계는 저장된 piecewise 제곱 속도에 `Σ2ds/(r_i+r_(i+1))`를 적용한 대수값이다. 새 차량 모델 적분은0이다.268 목표는 원래 근사 가속/제동·횡 allowance를 넘는 stress reference이고100m/s 수치 ceiling을 넘는 목표도 포함한다. 따라서10.027초는 실행 가능성이나11초의 물리적 하한이 아니다. O의+4.753초도 모두 회수할 수 있는 '추종기 낭비'가 아니다. 실제 타이어/엔진/구동기·목표 미달·진입 상태·원래 cursor 및 경계 분기가 섞인다. 원래 O가 목표보다 느렸기 때문에 더 안정적인 상태를 만들었을 가능성도 남는다.

이번 최고 실제 시간14.78초도11초보다3.78초 느리다. C+base의 작던 참조 시계 차이를 stress profile에 그대로 외삽하거나, 가까운 참조 시간만 보고 profile을 승격할 수 없다. 결과는 GT 진단이며 합법 픽셀296 개선은 아니다.

## 실패 전이에서 분리된 사실

O+268/C+268은22개 명령까지 같았고,23번의 **동일한 실제 pre-state와 nominal 조향**에서 처음 갈라졌다. 이때 두 목표와 기울기도 같았다(`r=83.657m/s, f=−195.056m/s²`, 실제 속도54.062m/s). O의 raw 요구−150.662는 brake0.3으로 제한됐고, C의 진행률 보정 raw 요구−81.657은 brake0.26870을 냈다. 이 최초 차이에서는 사영 목표 차이가 아니라 체인 항이 원인임을 현재 입력의 대수로 분리했다. 그러나 그 뒤의 서로 다른 폐루프 상태 이력을 하나의 제동 pulse 효과로 확정하지 않는다. 새 pulse나 counterfactual 전이는 실행하지 않았다.

C+268의99→103행동에서 post 경로 오차는0.095→0.405→1.375→2.817→4.760m로 증가했고, 다섯 행동 모두 뒤8/8 wheel-tick이 포화됐다. 작은 현재 횡오차에도 이미 큰 yaw·후륜 slip이 누적돼 있었다. 최종 행동은 gas0.899·brake0, 목표95.707 대 실제 pre67.539m/s, pre yaw3.671rad/s였다. 뒤 힘 벡터 요구는 최대 limit의6.13배였고8/8표본이 횡 요구만으로400N을 넘었다. nominal 속도 오차만으로 이 상태의 구동 요구를 정하는 한계가 보인다.

## 다음 가설 — 실행하지 않음

고정 경로 자체는14.78초를 실제 재현했다. 빠른 stress reference와 시간 영역 추종을 그대로 결합한 C+268은 닫고, 다음은 **미래 코너에 도달할 yaw/slip·실제 가감속 가능성까지 제한하는 속도 계획/실행의 연결**을 먼저 반증할 가치가 있다. 최초23번의 같은 상태에서 시작해 미래 진입 상태가 어떻게 달라지는지, 현재 저장 trace에서 제동·진행·조향/후륜 상태의 인과 후보를 먼저 좁힐 수 있다. 새로운 물리 전이가 필요하면 모델 자격·고정 조건·목적·비용을 별도 등록해야 한다.

이것은 C의 수학적 보정 전체나 profile 방법군을 버리는 판단이 아니다. 또한 O/C 식의 임의 가중 혼합, gain/pace sweep, 정지/불안정 상태별 사후 예외,268 profile 수리로 되돌아가지 않는다. 실제 미리 확보되는 감속과 바퀴별 힘 여유를 제약으로 삼아야 하며, 마찰 원·등분 하중의 planner 근사를 실제 source 한계로 바꾸어 부르지 않는다. 11초대 목표의 나머지3.78초가 가능한지는 미확인이다. J 정지 선택 대안은403의 별도 설계로 남겼다.
