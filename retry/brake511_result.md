# 511 — 실제 DEV 물리 속도목표 짝 비교 통과

승인 종료는 최신 사용자 정정에 따라 **2026-10-20 19:01:55 KST**다. 이번 응답의 앞선 10월16일 종료 판단은 잘못이었다. 기존 [497 정정](diagnostic497_correction.md)과 일치한다. 승인 원문과 개인 자료는 공개하지 않는다.

## 순수 게이트 복구

기존 순수 시험은 `59.199999999999996 != 59.2`에서 실패했고 실제 world/reset/action은0이었다. assembly COM norm 자체가 binary64이므로 실수 산술의 `60−0.8=59.2`와 마지막 비트가 다를 수 있다. 테스트는 관측 COM 속도에서 정해진 binary64 산술을 적용한 값과 정확히 같은지 확인하고, 수학적59.2와는 **1 ULP 이하**인지 별도로 검사하도록 수정했다. 이 허용치는 순수 산술 assertion에만 있다. 물리 목표 ±0.10m/s, 예측오차0.15m/s, 여유0.25m와 후보·조건·중단 규칙은 바꾸지 않았다. 순수3tests 통과 후에만 물리를 시작했다.

최초 실패 로그·계약·runner/test 원본은 private에 보존했다. [원래 계약](brake511_contract.json)을 덮어쓰지 않고 [실행 계약](brake511_execution_contract.json)에 수정 이유와 source SHA를 등록했다. 물리 실행은 한 번이다.

## 동결 조건과 관측 경계

510과 같은 검증된 DEV 초기 case 하나다. 첫24actions는 각 arm의 자기 현재 pixel 관측에서 `PixelAgent(adaptive=True)`를 한 번씩 호출한다. 이후 양쪽 모두24번째 steering을 유지하고 gas0이다. action25 직전 각자 실측 assembly COM 속력에서2m/s를 뺀 절대 목표를 설정한다. 초기·trigger model/관측/reference fingerprint와 목표가 양쪽에서 일치했다. 과거 trace는 실행 후 prefix 대조에만 사용했다.

매 hold의 요청 종료속도는 `max(절대 목표, 현재 속력−0.8m/s)`다. steady는 effective-mass torque 환산, response는 물리4tick 응답 역산으로 brake만 정한다. 미래 실측 상태·접촉을 명령 입력에 넣지 않았다. 명령은4tick 동안 고정하고 wrapper 경계에서만 목표·안전·효과를 판정한다. 정확한 현재 물리 상태와 지도에 접근하는 진단이므로 pixel-only 정책 자격을 뜻하지 않는다. HOLDOUT/SEALED 추가 조회와 새 seed는0이다.

## 다음 제어 변경의 범위

제동 의도는 raw brake 숫자보다 원하는 속도/감속도로 정의하고, actuator 계층에서 현재 접촉·휠 회전 응답을 반영하는 방향이 이 국소 결과와 맞는다. 조향·가속은 이번처럼 분리해 유지한다. 다음 실제 정책 검토는 기존 pixel 관측으로 속도와 필요한 상태를 추정할 수 있는지, 추정 오차 아래에서도 이 이득이 유지되는지부터 좁혀야 한다. privileged 모델을 그대로 제출 정책에 연결하지 않는다. 이번 짝 비교는 완료됐으며 남은26action을 임의 추가 실험에 사용하지 않았다.
