## 소스와 근사의 경계

[차량 소스](../core/vendor/car_dynamics.py)의 바퀴별 계산은 다음과 같다. `vf,vs`는 각 바퀴 축의 실제 속도이며 `R=0.54,I=1.6,dt=0.02`다.

```
omega += dt * 40000 * engine_multiplier * gas / (I*(abs(omega)+5))
브레이크: b>=0.9이면 omega=0, 그 외 양수이면 tick당 최대15*b 감소
Fx_raw = 82*(R*omega - vf), Fy_raw = -82*vs
q = hypot(Fx_raw,Fy_raw)/L_w
(Fx,Fy) = (Fx_raw,Fy_raw)/max(1,q)
omega -= dt*Fx*R/I
```

`L_w`는 접촉 tile의 마찰·잔디·손상 grip에서 정해진다. 이번398의4384개 wheel-tick에서 식과 live limit400N을 확인했다. **바퀴별 벡터 절단은 실제 소스다.** 그러나 `M*v²*κ`를 네 바퀴나 두 축에 등분하고 잔여 종력을 `sqrt(L²−Fy²)`로 배정하는 것은 planner 근사다. 소스에는 수직 하중이나 하중 이동을 풀어 마찰 한계를 나누는 계산이 없다. 각 바퀴는 자기 속도·방향·omega·관절과 Box2D 전이에 따라 다른 힘을 낸다. 네 바퀴 limit가 같다는 사실은 횡력 요구가 같다는 뜻이 아니다. 여기의 wheel-local 성분을 그대로 더해 차체 전방 가속이나 yaw 토크로 해석하지 않았다. raw tick마다의 바퀴 세계 방향이 저장되지 않아 그 재구성은 미자격이다.

후륜 gas 증가는 호출당0.1까지이며 wrapper가 같은 명령을4 raw tick에 반복하므로 상승 지연이 있다. 제동은 차체 감속 명령의 정확한 역함수가 아니다. 앞 조향은 관절각 ±0.4, 목표 차이에 비례하되 motor speed 최대3rad/s·유한 torque로 움직인다. [환경](../core/vendor/car_racing.py)은 요청 steer의 부호를 뒤집고 gas/brake를 넣은 뒤 `Car.step`과 `world.Step`을 호출한다. 따라서 양의 요청 steer와 음의 관절각을 부호 오류로 취급하지 않았다. 기존 effective mass·power 환산과 가속 clamp는 이러한 전체 전이의 보증값이 아니다.

## 제곱 속도 envelope의 자격 조건

양의 경로 진행과 충분히 작은 추종 오차라는 근사 아래에서만 `W=v², dW/ds=2a`를 쓴다. 실제 속도 크기의 시간 미분을 a라 두면 일반적으로 `d(v²)/ds=2v*a/σ`이며 σ=v를 보장하지 않는398의 큰 횡오차·slip 상태에 `2a`를 그대로 대입하지 않는다.

```
0 <= W_i <= C_i
W_(i+1) <= W_i + 2*A_i*ds_i
W_i <= W_(i+1) + 2*B_i*ds_i
```

여기서 C·A·B는 상태 범위와 지연을 포함해 자격이 있어야 한다. 현재 기록은 강한 입력을 체계적으로 가한 가감속 한계 자료가 아니므로, 관측 감속의 최솟값이나 마찰 상수를 그대로 '보장 B'로 삼지 않는다. 변속도·손상·접지·slip·조향 상태에서 동시에 확보할 수 있는 한계는 아직 미자격이다. 바퀴당400N이라는 upper bound만으로 감속의 lower guarantee가 나오지 않는다. 초기 실제 속도, 출발 시간 영역, 마지막 선분의 양의 결승 통과 속도와 공식 중앙 timestamp를 연결한다. 첫lap 출발0과 양의 종단을 같게 만드는 주기조건을 강제하지 않으며, 반복 lap을 계획할 때에만 별도 주기 정합을 검사한다. 임의 epsilon·마지막 cursor wrap·100m/s 초과 목표를 이용해 자격을 만들지 않는다.
