# Adoption check for the original policy with a higher global ceiling

This check evaluates the original hazard-scheduled pixel policy with its global
target ceiling changed from 28 to 40. It does not include the earlier learned
mask, additional distance constraint, or curvature wrapper. Two declared source
literals change; the legacy base-controller ceiling is overridden in the active
Agent. All other archive members and control parameters remain identical.

The candidate archive itself contains every policy module needed by the clean
worker. Its static import, dynamic-code, archive-size and member checks are
recorded separately from official server compatibility. The frozen candidate
archive bytes reproduce the locally evaluated policy; same-host execution does
not establish official container enforcement or fresh-machine parity.

`qualify_reset_replay.py` runs the frozen candidate on a saved DEV completion,
then resets the same actor and verifies the initial prefix again. A second cold
actor verifies the same prefix. It checks full observation hashes, exact action
bytes, package origins, legal pixel-only input, latency, memory and process
reaping. Older fault tests are reused only where the worker, supervisor, native
sandbox and active runtime path remain unchanged. Dependency and source hashes
bind this reuse; old composite-policy performance is not transferred.

Four new HOLDOUT road identities are registered before evaluation. Prior DEV,
HOLDOUT and interrupted registrations are excluded through stored identity
metadata. Each road uses both frozen arms once, with alternating AB/BA order.
No difficulty filter, performance-guided redraw or result-dependent setting
change is allowed. Actual resets must match the registered road and obstacle
hashes, then match between arms in recorded state and all four pixel frames.

The allocation is updated only after measured wall/CPU throughput, current
disk/memory, process availability and the authorization window support the
entire batch plus closure. A hash-bound readiness receipt must pass before any
worker or simulator is launched. The evaluator uses the operating cap in the
frozen plan, preserving the historical default for earlier plans. The total
limit is eight episodes, 2,000 actions each, at most 16,000 actions. The reserve
is not reassigned. Technical faults stop safely without automatic retries.

The preregistered completion-first rule preserves the current champion if any
pair is missing, technically invalid or censored, or if any original completion
is lost. With no loss, a new completion is positive evidence. Otherwise there
must be at least two common completions, a negative median paired lap change
and a mean paired lap ratio below one. There is no minimum percentage gain and
no zero-damage requirement. Damage is a separate warning. Common failures are
compared by progress, never by treating failure time as a lap.

Only one final aggregate is inspected. No frames, detailed failure trajectories
or policy telemetry are retained from the HOLDOUT. Four roads provide a small
descriptive adoption comparison, not a precise reliability estimate. SEALED
remains closed. Artifact and execution qualification plus the frozen outcome
rule control any adoption. A versioned manifest and canonical current-champion
pointer must preserve the previous archive, manifest and rollback history.

Private plans, identities, archives, dependencies, records and individual
endpoints stay outside this repository. Public outcome reporting is limited to
the authorized aggregate result and measured cost.
