312 — 코드·저장 결과 검토 완료, 새 실험은 실행하지 않음

다음 작은 반증 대상으로 **경로 점수의 조향 예측을 현재 296 추종기의 실제 식과 일치시키는 변경 하나**를 제안한다. 실제 gain·lookahead, 실행 controller, 페달 head, 지각·메모리, 기존 세 경로 후보와 비용 가중치는 고정한다. 성능 개선은 아직 검증되지 않았으며 현재 챔피언 296과 311의 실패 판정은 유지한다.

적용 계획 원문은 로컬에서 확인하지 못했다. 기존 112 감사도 두 원문 DOCX를 찾지 못했다고 기록했으며, 현재 Library 검색·읽기 기능도 노출되지 않는다. 로컬 20의 16개 방법군 원장은 스스로 WORKING NORMALIZATION이라고 명시한다. 이를 원문의 전체 canonical 원장이나 적용 계획의 재독 완료로 주장하지 않는다. 아래 검토는 그 16개 작업 분류에 이후 실제 코드·결과를 연결한 것이며, 원문과의 완전한 대응 확인은 남은 장애물이다. 별도 대규모 문서 감사는 수행하지 않았다.

가장 명확한 새 증거는 W09의 내부 예측 불일치다. 296 ZIP의 `choose_route`는 기본 lookahead로 목표점을 고르고 gain 없는 `atan(3.24*curvature)`를 사용한다. 실제 `nominal238_base`와 `parameter_agent`는 동결된 lookahead scale과 steering gain을 사용한다. smoothing·clip과 이전 명령은 양쪽에 이미 존재한다. 따라서 실행 조향을 복원할 수 있는 입력을 가지고도 연결 비용은 다른 조향을 평가한다.

보관 ZIP의 `choose_route` 165개, 서로 다른 AST 본문 5개를 검토했다. 다섯 본문 모두 기본 target·gain 없는 raw steer를 사용한다. 해당 이름의 함수가 없는 33개 archive는 별도로 집계했다. 이 검사는 보관된 코드 범위의 증거이며 모든 과거 실험의 부재를 무제한으로 입증하지 않는다.

기존 300의 정확한 296 두 TRAIN 주행 659행에서 선택된 경로만 산술 검토했다. 경로가 있는 638행의 실제 목표점 복원 오차는 0이고 nominal·최종 조향은 float32로 정확히 일치했다. 점수용 예측 조향은 378행에서 달랐다. 절대 차이는 평균 **0.007211rad**, p95 **0.024365rad**, 최대 **0.063000rad**다. 목표점 거리 차이 평균은 **0.861242m**다. clip 때문에 목표점 차이가 있어도 조향 차이는 없을 수 있다. 다른 후보의 순위 변화, 실제 충돌 회피, 완주 이득은 측정하지 않았다. 이 사실을 실패의 원인 확정이나 성능 개선으로 확대하지 않는다.

298/299는 실제 gain을 되돌렸고, 304는 이전 조향 anchor를 바꿨으며, 310은 비용 가중치, 311은 후보 용량을 바꿨다. 이번 제안은 **기존 실행 설정을 그대로 사용해 점수의 의미를 실행 식에 맞추는 것**이다. 세 후보·기존 tie 순서·거리 비용·connection weight를 그대로 둔다. 236 상호 배타 페달과 301/303 target-loss guard도 포함하지 않는다. gain과 lookahead의 효과를 따로 주장하지 않고 한 가지 예측 일관성 가설만 검증한다.

다음 실험의 고정 제안은 다음과 같다. 이번 312에서는 구현·실행하지 않았다.

1. 같은 306의 저장된 여섯 TRAIN 픽셀 입력으로 OFF가 296 행동·features·memory를 정확히 복원하는지 확인한다. ON은 같은 입력·이전 명령의 모든 기존 후보에 현재 추종기의 target·gain·clip·smoothing을 산술 적용한다. predictor와 실제 추종기 식이 정확히 같아야 한다. 다른 후보 생성이나 최종 행동 보정은 없다. 적어도 두 도로에서 기존 순위와 달라질 때만 native screen으로 간다. 변화가 없거나 OFF 불일치이면 중단한다. 이 replay는 새 closed-loop 성능 증거가 아니다.
2. 후보 하나를 freeze하고 기존 여섯 TRAIN 조건을 한 번씩 평가한다. 비교는 이미 저장된 정확한 296의 5/6 성공 결과이며 baseline을 다시 실행하지 않는다. 예상 약 **1,750~2,000 native**, 기존 306/311 실측 wall을 근거로 약 **60~90초**다. 지연·DNF에 따라 늘 수 있다. 총 hard cap은 **3,000 native**이며 현재 잔여 3,880 안에서 수행할 수 있다. source simulation·학습·별도 유료 자원은 0이다.
3. 사전 screen 통과 조건은 **기준선 완주를 하나도 잃지 않고 6/6 성공**, 또는 **동일한 5/6 완주 집합에서 공통 완주 평균이 최소 80ms 단축**이다. 손상은 별도 경고로 보고하며 임의의 자동 탈락 조건을 추가하지 않는다. 실제 DNF와 기술 오류·cap censor를 구분한다. 오류·censor가 있으면 통과시키지 않고 미관측 도로를 DNF로 만들지 않는다. threshold·계수·조건을 결과 뒤에 조정하지 않는다.
4. 이 screen으로는 승격하지 않는다. 통과해도 전체 TRAIN·미개봉 DEV 평가의 비용과 승격 기준을 별도로 등록한 뒤 결정한다. 이번 제안에는 그 자동 확대를 포함하지 않는다. DEV/HOLDOUT/SEALED는 열지 않는다. 추가 예산 요청은 **0**이며 예비 84,000은 사용하지 않는다. 승인 종료 시점 뒤에는 새 실험을 시작하지 않는다.

312 실측 비용은 **native 0, source physics 0, fit 0, actor 호출 0**, 산술·코드 집계 wall 2.794초다. 준비·문서 검토 시간은 이 집계에 포함하지 않았다. **누적 1,242,120 + 연구 잔여 3,880 + 예비 84,000 = B1,330,000** 그대로다. 정책·root agent·Participants·main·기존 백업을 변경하지 않았다. 공개 deliverable은 일반 분석 코드와 집계 세 파일뿐이며 원문·계수·ZIP·seed·픽셀·개별 trace는 비공개로 유지한다.
