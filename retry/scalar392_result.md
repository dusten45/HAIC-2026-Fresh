# 392 — 실제 진행률을 쓰는 제어식의 저장 행 반증

**양의 목표 속도에서 세 가지 대수·저장 행 검사는 통과했지만 전체 실행기 자격은 미충족**이다. N1의 정지 부근 제동99행에서 새 제동 요구가 사라졌고, `sigma=r`일 때 원래 식과 일치했으며, 움직이는 제동93행 중86행은 여전히 제동했다. 그러나 목표0의 출발 분기가 없고, 원래 cursor와 실제 경로 사영 구간이 다른 행이 많아 같은 위치에서의 체인 법칙 구현으로 확대할 수 없다. 새 명령을 실제/모델 다음 상태에 적용하지 않았다. ## 근거와 사전 등록

지정된 [정적 분석 커밋의 문서](https://github.com/dusten45/HAIC-2026-Fresh/blob/3e584dff988f0b90fce3dd563b7f6351a13d21f8/retry/static_control_audit_20261016.md)를 Git으로 읽었다. 로컬에 커밋 객체가 없어 해당 원격 브랜치만 fetch했으며 다른 작업의 파일 경로를 사용하거나 브랜치를 merge하지 않았다. 문서 내용 hash를 계획에 묶었다.

265와268/269는 **같은 제어식**을 사용한다. 268은 profile 배율을 바꾼 것이며, N1의 기존14.78초 완주는 정지 제동 가능성이 식에서 제거됐다는 증거가 아니다. 이 점을 기존 연구 설명에도 명시했다.

실행 전에 알려진 TRAIN인390 A-O0의247행과 A-N1의259행, 원래 고정 경로·profile·pre-state·cursor에서 읽은 `r,f,v`, 원래 clamp·페달 환산, 아래 진행률 정의·탈락 기준을 동결했다. 총506행·CPU60초 상한이며 wrapper·actor·모델 적분·학습·SEALED 조회 상한은 모두0이다. 기존 페달을506행 모두 재계산해 float32 출력 일치를 확인한 뒤 feedforward 항 하나만 독립 계산했다.

```
a_old = f + 1.5 (r-v)
a_alt = f (sigma/r) + 1.5 (r-v),  r>0
```

각 행은 원래 실제 상태만 입력으로 쓴다. 새 gas/brake를 다음 행의 속도·바퀴·cursor·profile에 반영하지 않았다. 출력은 고정된 대수식의 요구값이지 달성한 가속도가 아니다.

## sigma와 경계의 정의

실제 pre-position을 닫힌 다각선 경로의 모든 선분에 유클리드 최근접 사영했다. **유일한 최근접점이 선분 내부에 있을 때** 그 단위 접선과 실제 velocity의 내적을 `sigma`로 썼다. 이는 해당 직선 조각에서 사영 arc의 국소 시간 미분이다. 속도 크기·차체 전방속도·cursor 차분이나 실제 다음 상태에서 계산한 속도가 아니다.

다각선 조각은 내부 곡률0이므로 여기서는 Frenet 분모를 쓰지 않는다. 매끄러운 곡선의 `v_t/(1−κe_y)`를 흉내 내면서 곡률·횡오차 항을 생략한 근사는 아니다. 꼭짓점이나 최근접점의 중복에서는 미분이 정의되지 않으므로 계산 자격을 주지 않았다. float64에서 정확히 같은 최소 거리인 경우를 tie로 판정했고, 분모나 거리·부호 판정에 임의 epsilon을 넣지 않았다. 수치적으로 가까운 비유일성까지 인증한 것은 아니다.

- **r=0:** 나눗셈과 대체 명령을 만들지 않고 `zero_target_unqualified`로 보류했다. 출발·정지·재출발 규칙을 발명하거나 epsilon으로 양수 목표를 만들지 않았다.
- **후진:** 음의 sigma를 0으로 자르지 않았다. 식의 대수값은 계산하되 정방향 추종 자격에서는 제외했다. N1의 음수34행은 −4.44e−11~−2.58e−19m/s 규모였고, 별도 기술 기준인 sigma<−0.1m/s의 의미 있는 후진은0행이었다. 작은 음수를 정지0으로 바꾸지는 않았다.
- **cursor:** 원래 `r,f`를 바꾸지 않았다. 최근접 선분과 원래 cursor 선분이 다르거나 cursor 투영이 끝점에 고정된 행은 동일 위치의 체인 법칙으로 보지 않았다. 따라서 이 경우 `a_alt`는 진행률 보정을 넣은 독립 실행식 비교다.
- **폐곡선:** 마지막→첫 선분도 포함했다. sigma는 arc 차분이 아니므로 L→0 점프가 큰 속도로 들어가지 않는다. 진단용 unwrap은 부호 있는 최소 주기 차이를 쓰며 반 바퀴 모호성은 보류한다. 원래 lap별 profile 분기 전환도 별도 표시했다.
- **불연속:** cursor 변화와 최근접 사영의 주기 보정 변화 차이가2구간을 넘으면 전환 양쪽을 표시하도록 등록했다. 이번 기록에는0행이었다. O0의 lap profile 분기 전환1행은 같은 매끄러운 추종식의 자격에서 제외했다. 관측되지 않은 점프에서의 동작을 검증했다고 주장하지 않는다.

## 관측 결과와 탈락 판정

미정의 수·비유한 결과, `sigma=r` 동일성 실패, 양의 목표에서 정지 대수값이 양수가 아님, 실제 저속 제동 행에서 새 음의 요구가 남음, 정상 제동의 전면 삭제를 탈락으로 사전 등록했다. 정상 제동 표본이 없으면 통과가 아니라 미확인으로 두었다. 도메인 밖 행을0으로 채우거나 평가 분모에서 숨기지 않았다.

| 검사 | O0 | N1 |
|---|---:|---:|
| 원래 저장 행 | 247 | 259 |
| r>0 / 대안 명령 계산 가능 | 247 | 258 |
| r=0 보류 | 0 | 1 |
| `sigma=r` 동일성 검사 통과 | 247/247 | 258/258 |
| 양의 목표에서 `v=sigma=0 → a=1.5r>0` 대수 검사 | 247/247 | 258/258 |
| 실제 속도<0.1m/s이며 원래 제동한 행 | 0 | 99 |
| 그중 새 제동 요구가 남은 행 | 0 | 0 |
| 움직이며 원래 제동한 행에서 새 제동 유지 | 52/53 | 34/40 |

정지 대수 검사는 저장된 양의 `r,f`에 대한 항등성 검사이며 새 실제 상태를 만들거나 원래 상태를 교체해 평가한 주행이 아니다. 실제 저속 기준0.1m/s는390의 기존 기술 정의를 그대로 썼다.

N1의99행에서 새 raw 가속 요구는 **109.0805~109.1324m/s²**, 원래 clamp를 거친 gas는 약0.03457~0.03472이고 brake는0이었다. 실제로 재출발했는지는 측정하지 않았다. 움직이는 제동은 합계**86/93행**에서 남았다. `v>r,f≤0,sigma≥0`이면 두 항이 음수이므로 제동이 유지되는 대수적 조건도 확인했으나, 실제 해당 표본은 O0 한 행뿐이다. 이 결과가 모든 선제 제동의 적절성을 보장하지는 않는다.

중요하게도 **정지 부근99행 모두 원래 cursor와 최근접 사영의 선분이 달랐다.** 전체506행 중 정방향·동일 선분·분기/점프 문제가 없는 체인 법칙 적용 부분집합은192행이다. 따라서 “정지 제동을 없애는 대수적 성질을 확인했다”와 “목표와 진행률이 같은 arc에서 정의된 완전한 추종기를 검증했다”를 분리한다. 후자는 아직 미자격이다. N1 첫 행의 목표0·중복/끝점 사영 문제 역시 미자격으로 남긴다.

## 판단과 다음 최소 반증 — 미실행

이번에 배제한 설명은 양의 목표에서 실제 진행률을 곱해도 정지 제동이 반드시 남는다거나, 이 보정이 단순히 모든 제동을0으로 만든다는 것이다. 기존268의 완주를 제어식 변경의 효과로 해석하지 않는다. 정상 주행에서의 제동 시점·미래 곡률 제약·종횡 힘 결합·실제 재출발·lap 개선은 미측정이다.

다음 최소 제안은 **같은506개 저장 상태·원래 경로·원래 profile을 유지하고**, 최근접 실제 arc 한 점에서 목표 `r`와 기울기 `f`도 일관되게 읽어 현재의 원래 cursor 기반 계산과 분리하는 것이다. 새 parameter·경로·profile·상태를 탐색하지 않는다. 같은 CPU60초/506행, wrapper·actor·모델 적분·학습0으로 먼저 등록할 수 있다. 양의 목표의 정지·동일성·제동 유지 검사를 반복하고, 달라지는 `r,f`와 경계 부적격 행의 수를 공개한다. r=0과 lap 출발/종단·사영 다중성은 별도 규칙 없이 계속 보류한다. 이 비교를 통과하기 전에는 새 주행이나 큰 최적화를 시작하지 않는다. **이번 단계에서는 실행하지 않았다.**

실행 CPU0.183초·wall0.123초, 신규 wrapper·actor·모델 적분·학습·SEALED 조회·유료 자원은 모두0이다. Git fetch·준비·문서 시간은 전부 계측하지 않았다. 연구 잔여34,139회·예비84,000회 미사용·296·보호 원장·SEALED16·종료2026-10-20 19:01:55 KST를 유지했다. 원시 위치·행동·계수·지도·개인 자료는 비공개로 보존했다. 계획·방법론 원문은 부모의 전체 재독과 전달 지침을 근거로 하며 실행기의 직접 완독을 주장하지 않는다.
