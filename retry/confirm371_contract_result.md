# 371 미개봉 DEV의 단일 동결 paired 확인 계약

**계약만 준비했다. 새 시뮬레이션·actor 호출·split 개봉·champion 교체·예산 배정·예약은 없다.** 연구 **20,499회**, 최종 예비 **84,000회**를 보존했다. 이번에는 297의 조건 파일과 성능 결과를 읽지 않았다.

등록 메타데이터의 정확한 역할은 **`DEV_COMPLETION_CEM_297`**이다. 297에서 파라미터 draw 전에 등록한 12조건이며, 단일 TRAIN winner를 동결한 뒤 296와 한 번 비교하기 위한 조건부 DEV였다. 298·299로 같은 집합이 transfer됐고 309에서도 기존 297의 미개봉 DEV로 참조됐다. 해당 seal들은 성능 미개봉을 기록하고 있다. 이 역할은 공식 HOLDOUT이나 최종 SEALED가 아니다. `sealed`라는 표현은 성능 봉인 상태이지 split 재분류가 아니다.

297·298·299·309의 DEV 결과 폴더와 성능 opening 표식, 297의 309 개봉 표식은 없다. 369의 기존 job 신원 감사는 해당 집합의 실행 0건을 확인했고, 370은 별도의 기존 296 DEV만 실행하며 보호 표식을 보존했다. 과거 369에서 신원 메타데이터를 대조한 이력이 있으므로 모든 신원 정보에 한 번도 접근하지 않았다고 주장하지 않는다. **성능 피드백이 미노출이라는 구분**이다.

오늘은 `fresh-DEV-private.json`과 세 `split.json`의 **존재·크기·mtime만 확인**했다. 내용을 읽거나 parse·hash·복사하지 않았다. 등록 manifest hash는 기존 seal의 메타데이터를 참조했으며 조건 내용에서 다시 계산하지 않았다. selection-contract에서는 split 역할·등록 목적·동결 시각·exclusion snapshot hash만 확인했다. 비공개 조건·seed·결과를 게시하지 않는다.

제안 arm은 **A=champion 296** (`0a6c5e286e87d75498c5aec1174c7af3fd54f6efa34b0d83ca1efba5d404a937`), **B=동결 365** (`65df88a5b2391675e49c3f39259adab0f8a791da5ab58ea620cbe130b0a9ce34`)다. 12조건 × 두 arm = **24개 실제 에피소드**를 각각 최대 2,000행동으로 수행하면 최대 비용은 **48,000행동**이다. 현재 연구 잔액보다 **27,501회가 더 필요**하다. 새 act·commit 각각 최대 48,000회, 환경/actor reset 24회, 최대 step raw tick 192,000 + 예상 reset tick 1,224다. 실제 소비만 차감하며 2,038 내부 상한을 자동 적용하지 않는다.

독립 확인의 중간 결과를 보고 예산을 보충하거나 유리할 때만 계속하는 운영은 피해야 한다. **전체 48,000 최악 상한의 별도 승인·배정 전에는 성능을 열지 않는 것**을 제안한다. 현재 잔액만으로 24에피소드 완료를 보장할 수 없고, SEALED용 예비 84,000회를 이 비용으로 돌리지 않는다. 이번에는 부족분도 배정하지 않았다.

개봉 전 계약은 다음으로 제안한다.

1. 새 명시적 실행 지시에서 기존 조건부 DEV를 **365 대 296 단일 동결 확인**에 쓰도록 지정한다. 옛 297 CEM 계약 자체가 현재 365의 자동 개봉 허가는 아니다. 두 ZIP/member/model hash, 입력 전용 worker·evaluator·환경·런타임, 읽기 전용 관측기, 등록 manifest 참조, 원래 조건 순서·등록 AB/BA 순서, 비용·중단·판정 기준을 성능 질의 전에 동결한다. 새 조건 추출·대체·재표집은 없다.
2. 각 arm은 별도 새 환경·actor reset을 사용한다. 같은 비공개 조건·seed·options에서 첫 행동 전 초기 영상·기하·등록 장애물 hash·기록 가능한 물리·접근 가능한 RNG를 paired로 확인한다. 이 집합에는 아직 실제 296 baseline 결과가 없으므로 둘 다 새로 실행한다. 초기 영상 hash는 승인된 첫 reset에서 확보될 수 있으며, 과거 DEV의 hash를 대신 쓰지 않는다. 이후에는 각자의 관측·전체 반환 제어·정상 기억으로 진행하고 갈라진 관측을 강제로 같게 만들지 않는다.
3. 같은 CPU·메모리·입력·timeout 제한을 적용한다. 기존 자격이 있는 각 정책의 계측 코드 차이는 hash로 묶어 공개하고 정책 ZIP이나 제어 계산을 수정하지 않는다. GT는 읽기 전용 초기 신원 확인·평가 캡처와 사후 지원 라벨에만 사용한다. 후보의 실제 routing 포함을 점검하며 low 플래그만으로 누락을 판정하지 않는다.
4. 공식 완주·은퇴가 먼저면 종료하고, 그렇지 않으면 2,000 상한·현재 승인 종료 시각·기술 실패에서 멈춘다. 공식 종료 없는 상한은 protocol censor다. 정상 DNF는 두 번째 arm과 다음 예정 pair를 계속한다. 기술·source·reset·합법성·무결성 오류 또는 알려진 지원 직접/출생 지원 retained 누락이 나오면 남은 pair를 멈추고 부분 결과·미측정을 보존한다. 확인된 잘못된 fixture 간 low 양성 전파도 자격 반례다.
5. 연결이 끊기면 기존 프로세스와 저장 기록부터 확인한다. 살아 있는 실행을 중복 시작하지 않는다. 죽은 실행의 마지막 단계가 불명확하면 유리한 재시도를 하지 않고 기술 검열·실패로 남긴다. 이미 저장된 결과로 마감 기록을 복구하는 것만 허용한다. 자동 재실행·case 대체·budget/cap 연장·추가 인증 run은 없다.

주요 지표는 **공식 완주 수**, paired 완주 추가·상실, 양쪽 완주 조건의 공식 결승선 중앙 통과 lap 차이(365−296 평균·중앙값·합계·각 조건)다. DNF에는 가짜 lap을 주지 않는다. 양쪽 DNF의 진행률·종료 원인은 공식 미완주 순위에 맞춰 조건별로 보고하되 임의의 전역 가중 점수로 합치지 않는다. 접촉·DAMAGE·invalid·실제 비용은 진단으로 남기고, 합법성 제한은 별도 필수조건으로 둔다.

**승격 검토 자격**은 다음처럼 제안한다.

- 24개 모두 확정된 비검열 공식 결과이며 후보의 알려진 지원 직접·출생 지원 retained 누락이 각각 0이고 확인된 잘못된 low 전파·합법성·기술 실패가 없어야 한다.
- 새 paired 집합에서 `C365 > C296`이면 완료 수 기준의 후보 우세다. 공통 완주 시간 비용도 숨기지 않는다.
- 완료 수가 같으면 공통 완주 평균 `lap365 − lap296 < 0ms`를 엄격히 요구한다. 동률·공통 완주 없음이면 296를 유지한다. 완료 수가 적으면 296를 유지한다.
- 모든 개별 완주 추가·상실을 보고한다. 총 완료 수 증가가 있을 때 개별 한 조건 상실만으로 사후 veto를 추가하지 않으며, 지원점 게이트는 독립적인 필수 전제다. DAMAGE 가중치·사후 허용 오차·새 유의성 기준을 만들지 않는다.
- 여기서 **새 296의 완료 수는 미정**이다. 기존 반복 DEV의 10완주나 “11–12면 개선”이라는 절대 기준을 새 12조건으로 옮기지 않는다.
- 기준 충족은 **별도 명시적 승격 검토의 자격**이지 자동 pointer 변경이나 최종 공식 인증이 아니다. 296 rollback과 원본을 유지하며 실제 승격은 따로 지시돼야 한다. 부분·검열·기술 실패·지원점 반례로는 자격을 통과하지 못한다.

결과를 본 뒤 **이 12조건에 맞춘 재튜닝은 통과·실패 모두 금지**하는 계약을 제안한다. 새 threshold·특징·head fitting·365.1 대체 후보·조건별 예외·같은 집합 재평가를 하지 않는다. 승격 검토를 통과해도 365 bytes는 이후 SEALED까지 유지한다. 수정이 필요하면 이 확인 결과를 새 후보의 증거로 옮길 수 없으며 별도 연구 계약과 독립 증거가 필요하다. 최초 노출 시 사용한 정책 hash와 모든 24개 또는 중단된 질의를 원장에 남기고 집합을 영구적으로 성능 노출 상태로 기록한다. 다시 미개봉으로 부르지 않는다. 우세가 미리 명백해 보인다는 이유로 임의 조기 종료하거나 일부 결과를 감추지 않는다.

현재 알려진 tradeoff는 반복 DEV **365 12/12 대 296 10/12**, 공통 10조건 평균 **1.036초 지연**, 중앙값 1.330초·합계 10.360초 지연이며 열 조건 모두 느렸다는 것이다. 두 crash→완주 개선은 사전 완료 수 우선 규칙에서 의미가 있지만 속도 개선은 아니다. 공식 기준은 완주가 미완주보다 앞서고 완주끼리는 실제 lap이 짧을수록 우수하다는 것이다. 여러 seed의 완주 하나와 몇 초를 교환하는 보편적 총점식을 만들지 않는다. 반복 DEV는 이미 champion 선택에 사용됐으므로 독립 확인을 대신할 수 없다.

297 집합은 성능 미노출 상태에서 단일 동결 후보를 사전에 확인하는 데 사용할 수 있지만, **DEV 역할을 공식 HOLDOUT으로 재분류하거나 작은 12조건을 편향 없는 모집단 보증으로 해석하지 않는다**. 신원 메타데이터 노출과 조건 생성·분포의 한계, 한 pair/조건의 작은 표본을 남긴다. 미검증 양성 전이 62개와 기존 출생 GT 누락 직접 12개·retained 16개 문맥도 새 확인 결과만으로 해결됐다고 주장하지 않는다.

**별도 SEALED 최종 검증은 남아 있다.** 현 champion manifest는 `G5_SEALED=PENDING_CLOSED`, 보호 query ledger는 SEALED `episodes_used=0`, 현재 단계 허용 질의도 `0`이다. 원래 계약에는 별도의 SEALED 16조건이 등록돼 있고 개봉 표식은 없다. 조건 내용·결과를 읽지 않았다. 최종 SEALED의 실행·권한·판정 계약은 별도로 필요하며 이번 DEV 확인이 이를 대체하지 않는다. 예비 **84,000회는 전액 그대로**다.

이번 감사 비용은 native·actor·환경 reset·학습·후보 수정 **0**이다. metadata 감사 벽시계 2.236초·CPU 0.923초이며 코드 작성·git 전체 시간은 아니다. 연구 **20,499회**, 누적 wrapper 행동 **1,300,064회**, 예비 **84,000회**를 v388에 그대로 기록했다. main·공식 Participants·champion 296·기존 357/365·사용자 변경과 백업을 보존했고 비공개 조건·원문·모델·개인 자료를 게시하지 않았다.
