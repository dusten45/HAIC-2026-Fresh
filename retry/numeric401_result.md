# 401 — 반올림 자격 검증과 조건부 고정 2×2 모델 비교

새 수치 기준과 높은 slip snapshot 분기 자격을 통과한 뒤, 등록한 네 모델 arm을 모두 실행했다. **pace1.0+C는 N1의 기존 실패 arc에 안전하게 도달했고, 공동 선택 두 arm은 출발하지 않아 미도달 검열이었다.** 이는 해당 모델·경로·구간의 정보이며 실제 주행 개선이나296 승격은 아니다. 기존400의 엄격한 정적 미자격은 그대로 보존했다. [집계 결과](numeric401_result.json)

## 관측 잔차와 독립적인 수치 기준

원래 pace1.0 profile·입력·공식 물리·기존 코드를 바꾸지 않았다. 실행 전에 연산 오차식·적용 범위·대조군·중단 기준을 새 계획에 동결했다. binary64 입력을 정확히 Decimal로 옮겨90자리로 부등식을 독립 평가했다. 관측된2.27e−12를 tolerance로 사용하지 않았다. [수치 코드](numeric401_audit.py)

단위 반올림을 `u=2^−53`, `γ_n=nu/(1−nu)`로 두었다. 정상 범위의 round-to-nearest 연산과 올바르게 반올림되는 sqrt를 전제로 한다. 입력은 저장된 binary64 값 그대로이며, 양의 항을 더하는 RHS의 연산 오차와 sqrt로 저장한 속도를 다시 제곱하는 오차를 함께 제한한다.

- drive: `A=min(a_rear,80000/(v_i+2.7)/M_eff)`의 add·두 division은3회다. `v_i²` 1회, `2*A*ds` 2회, 양의 합1회를 보수적으로 합쳐 RHS 상대 오차를γ₆ 이내로 잡는다. sqrt 결과의 저장과 재제곱에 따른 두 상대 반올림 인자를 포함하면 `γ₈*(v_i²+2*A*ds)`가 상한이다.
- brake: A 계산이 없는 RHS를γ₄로 제한하고 저장 sqrt와 제곱 효과를 포함해 `γ₆*(v_next²+2*B*ds)`를 쓴다.
- 곡률 상한: division·sqrt·저장 속도의 제곱을 보수적으로 묶어 `γ₄*C`를 쓴다. 정확한100² cap과 min은 추가 팽창을 만들지 않는다. 2를 곱하는 연산도 보수적으로 횟수에 포함했다.

이것은 **profile 생성·표현의 반올림과 양립하는 수치 후방 일관성 기준**이다. 저장된 숫자의 정확한 실수 부등식이 모두 참이라는 인증이 아니다. 정상·유한 입력, 양의 ds, 초기0·양의 종단을 확인했고 overflow/underflow·큰 상쇄·임의 알고리즘·물리 모델 오차로 적용 범위를 넓히지 않았다. 90자리 평가 오차는 이번1e−12와 상한 간 여유에 비해 매우 작지만 구간 산술 인증을 했다고 주장하지 않는다.

대조 검사는 profile을 읽어 판정하기 전에 실행했다. γ₄/γ₆/γ₈ 각각에 세 규모(0.001,2,10000)의 비양수 조건과 **이론 상한의4배인 양의 위반**을 넣어 모두 올바르게 분류했다. 별도로 binary64 `sqrt(2)`의 정확한 제곱은2보다 조금 크지만 이론 band 안임을 확인했다. profile이나 성능 입력을 바꾼 대조가 아니다. 상한보다 작은 진짜 양의 위반은 반올림과 구분할 수 없으므로 그 영역을 '정확히 실행 가능'으로 부르지 않는다.

| 독립90자리 판정 | 정확한 양의 잔차 수 | 최대 잔차 m²/s² | 최대 잔차/해당 이론 상한 | 상한 초과 |
|---|---:|---:|---:|---:|
| drive |72/238 |1.6254e−12 |0.3600 |0 |
| brake |23/238 |1.6248e−12 |0.3445 |0 |
| C 상한 |14/239 |6.5011e−13 |0.5143 |0 |

고정밀에서도 작은 양의 잔차가 남았다. 400의 float64 계산과 비교해 brake·C에서 더 많은 양의 잔차도 드러났다. 따라서 '전부 뺄셈 오차라 사실0'으로 지우지 않았다. 모두 생성·저장 연산에서 도출한 band 안이므로 **새 수치 자격만 통과**시켰다. 이전400의 판정·profile·보고서를 고치거나 source 보장 감속/등분 횡력의 가정을 인증한 것은 아니다. 숫자 크기에 맞춘 사후 허용오차나 profile 수리는 없었다.

## 높은 slip 분기 복원·독립성 자격

기존400의274명령·1096tick 연속 재생 통과는 소스 hash를 확인해 재사용했고 다시 과금하지 않았다. 새 단계에서는 N1의 저장398 명령93개를 연속 재생해 pre94에 도달했다. 이 상태는 높은 slip 구간이며, 그 부모 모델의94번 전이와 새 snapshot의 동일 명령 전이를 비교했다. 새 snapshot을 만드는 동안 상태를 바꾸지 않았는지도 확인했다. [분기 코드](branch401_gate.py)

새 분기의 한 행동 오차는 속도4.83e−6m/s·yaw3.10e−6rad/s·위치0m였고 기존391 기준과 충돌·손상·접촉 판정을 통과했다. 6후보를 정순·역순으로 독립 평가하고 양쪽의 reference를 반복해 결과가 정확히 같았다. 부모 모델과 입력 snapshot hash는 변하지 않았다. 이 자격에는432모델tick·world15개를 사용했다. 전체 solver warm-start 복원이나 모든 상태의 분기 자격을 주장하지 않는다.

2×2 중에도 각 후보의 초기 body/tile/progress 일치와 부모·입력 불변성을 확인했다. 선택한 후보의 예측과 연속 부모 전이를 매행 기존391 기준으로 대조했다. 최초 자격 실패라면 전체를 중단하도록 했으며 이번에는 실패가 없었다. J arm의 실제 선택은 거의 정지 상태에만 머물렀으므로 그 매행 검사가 새로운 고속 counterfactual 순위 자격을 넓혔다고 해석하지 않는다.

## 고정 2×2 결과

N1의 같은 초기 상태·경로·원래 profile을 사용했다. profile 축은1.5/1.0, 실행 축은C397+pursuit/고정6후보의 한 행동 공동 선택이었다. gain·clamp·pedal 환산·후보 집합을 탐색하지 않았다. J 후보는 `조향[pursuit,현재 앞 관절각 유지,중립] × 페달[nominal,coast]`이며 환경의 조향 부호를 반영했다. 안전한 후보 중 `(다음 횡오차, |yaw|, −진행량, 등록 순서)` 사전식으로 골랐다. nominal pursuit memory 갱신 방식도 실행 전에 고정했다. [실행 코드](factorial401_run.py)

각 arm은 기존398 N1의 중단 arc에 도달하거나160행동 상한까지 실행했다. 3m 오차·충돌/손상·접촉 상실·의미 있는 후진의 안전 기준을 유지했다. 안전 위반과 목표 도달이 같은 행동이면 안전 실패로 판정했다.

|---|---:|---|---:|---|---|
| pace1.5+C |99 |도달하나 안전 위반 |3.2375m |안전 성공 시간 없음 |모델 안전 중단 |

pace1.5+C는398 실제 N1의99행동 실패를 재현했다. pace1.0+C는7행동 뒤인106행동에 목표를 넘었다. 실제398의 끝 시각7.92초와 비교해 같은 arc 도달 관측 구간은약0.48–0.56초 늦다. 안전과 속도를 함께 개선한 것으로 세지 않았다. 이 시간은 lap이 아니며 공식 완주·실제 변경 명령 검증도 아니다.

J 두 arm은 모두160번 내내 후보 index3(현재 앞 관절 유지+coast)을 선택했고, 최대 속도는약9.16e−11m/s·진행 arc는0이었다. 횡오차와 yaw를 진행보다 먼저 최소화하는 한 행동 사전식 목적이 출발하지 않는 해를 고른 것이다. 작은 오차를 성공으로 승격하지 않았다. 순서를 바꾸거나 progress 보너스·최소 gas·launch 예외를 추가해 같은 조건을 재실행하지 않았다. **이6후보·선택 recipe는 구동 목적을 달성하지 못했으며**, 공동 제어 전체나 더 긴 계획의 실패를 뜻하지 않는다.

등록된 해석상 E 단독이 해당 모델 구간을 통과했다는 정보는 얻었다. 그러나 J 단독은 움직이지 않아 두 방법의 동등한 주행 우열·유용한 상호작용은 식별하지 못했다. 따라서 'profile만으로 충분'의 범위는 **이 고정 C397·경로·초기 상태·모델 구간**이다. 전체lap·다른 조건·source 보장 envelope·296 승격으로 확대하지 않는다. 실제 profile 변경이 해당 구간에서 안전할지도 별도 실제 검증 전에는 미확인이다.

다음 판단에 남은 문제는 전진과 도달을 먼저 충족하는 공동 제어 목적의 자격, 그리고 고정 보수적 profile의 실제 paired 검증이다. 새 목적·후보·gain·실제 주행을 이번 결과 뒤 추가하지 않았다. 11초 목표의 하한이나 불가능성 결론도 없다.
