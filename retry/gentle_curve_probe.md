# Stage91 — 고정 게이트의 곡률 계수 7·8·10·14

동일한 기존 DEV preservation 조건에서 기준7과 후보8·10·14를 사전 순서대로 각 한 번, 새 reset으로 실행했다. **네 설정 모두 공식 완주**했고 후보 셋 모두 이 조건의 랩을 단축했다. 가장 빠른14는55.280초로 기준보다4.280초 빠르다. 10은2.000초 빨랐지만 손상.6과 충돌 판정 행동3개가 있었다. 계수와 성능·접촉의 관계는 단조롭지 않으며, 한 조건의 제한된 동작 범위 검사다. 광범위한 튜닝, 10초대 달성 검증이나 챔피언 승격은 하지 않았다.

## 사전 계약과 재현

모델·특징·픽셀 마스크·경로·조향식·속도 추정·추적·age0 거리 상한·전역28을 고정했다. 다음 조건을 모두 만족할 때만 기존 계수7 대신 지정 계수를 썼다.

- 경로 목표 존재, 전체 추적 장애물로 계산한 `near=false`.
- 선택 목표의 곡률 `.015≤|k|≤.05`.
- 기존 제어기가 계산한 평활 조향 절댓값≤.18. 게이트는 출력float32 반올림 전의 기존 `previous_steer`를 사용한다.

입력은 기존 픽셀 정책이 가진 값뿐이다. 원 제어 호출은 한 번이며, 그 결과의 조향과 상태를 보존하고 최종 목표가 증가할 때 가속·제동만 다시 계산했다. 원 거리 상한 진단은 현재 입력에서의 기준7 계산으로 보존하고, 별도 진단에 실제 적용 목표·차이를 기록했다. GT·환경 객체·세계좌표·seed·행동번호는 actor에 전달하지 않았다. 독립 actor의 파일 내용 접근 제한 런타임을 재사용했다.

기준7은 **59.560초·손상0**, 저장된 전체 관측 프레임·행동·학생 마스크까지 정확히 재현했다. 네 실행의 초기 전체 관측·물리 상태·도로 형상·장애물 배치도 일치한다. 각2,000행동, 합8,000행동 상한이며 native horizon은 그대로다. 완주를 잃으면 더 큰 계수는 미실행으로 남기도록 고정했지만 이번에는 해당하지 않았다. 손상만으로 완주한 설정의 랩을 제외하거나 다음 실행을 중단하지 않았다. Stage90 제안의400ms 문턱은 이번 사전 계획에서 제거했다.

## 실제 게이트 노출과 제어 변화

시간은 공식 finish 시점에서 자른 시뮬레이션 시간이다. 아래 목표·가속·제동 Δ는 **각 실행 자신의 현재 입력**에서 고정된 기준7 식을 적용했을 때와 비교했다. 별도 정책 호출이나 같은 상태에서의 추가 환경 행동은 없다. 후보별 입력·궤적은 분기하므로 평균 Δ끼리의 차이를 실제 랩 효과로 치환하지 않는다.

가속·제동 포화 때문에 목표가 높아져도 행동이 같을 수 있다. 전체 랩의 throttle 평균은7/8/10/14 순서로.13513/.13318/.14498/.13402, brake 평균은.04933/.04681/.04612/.04727이다. 전체 brake>0 시간은28.24/26.56/26.56/25.76초다. 이 전체 평균은 서로 다른 폐루프 궤적의 기술통계다.

세 후보 모두 첫26행동과 그 관측·상태는 기준과 같았다. 첫 행동 차이는 동일 입력의27번째 행동에서 브레이크가.41272→.37251/.29903/.17150으로 바뀐 것이고, 조향은 모두−.07839264로 같았다. 관측은28번째부터 달라졌다. **제어의 조향식 보존**과 이후 **실제 조향 궤적의 동일성**은 구분한다.

Stage90에서 같은 기준 캐시의7→8 게이트 노출은7.84초, 즉시 목표 증가 평균1.056m/s였다. 이번 실제8의 노출은7.04초·증가1.052m/s, 랩은3.760초 줄었다. 캐시 산술과 폐루프 랩 개선은 서로 다른 측정이며, 노출 시간이나 목표 증가를 회수한 랩 시간으로 계산하지 않았다. 14의 더 큰 즉시 목표 증가도 다른 DEV에서 같은 이득을 보장하지 않는다.
