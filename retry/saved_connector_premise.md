# Saved connector premise gate

`saved_connector_premise.py` extracts the frozen pure `connector_clear` function from a trusted, hashed policy source and applies it to saved selected connector endpoints and the exact obstacle tuples available to the route decision. It imports no policy or simulator, executes no Agent action, and generates no new scene. The plan fixes the earlier problem onset, source identities, first-gate deadline and stop rule before this arithmetic. A physical-obstacle proxy cannot substitute for an obstacle input that the policy did not have.

The origin's road support and its obstacle clearance are separate questions. An earlier mask-based initial-edge checker rejected the origin outside the planning support and returned the original route on both acceptance and rejection. It therefore produced no route or action treatment. The separate unknown-origin research candidate used the existing radial obstacle margin, searched the existing supported start corridor when the original connector failed, and returned the original route if no alternative was available. Its fallback did not invoke no-route braking. It was evaluated as a separate research candidate, with later independent development evidence mixed or neutral; its absence from the active baseline is not an omission or regression.

In the current saved-record audit, the existing predicate rejected connectors only after the earliest sustained heading-problem onset. An earlier violation against privileged physical obstacle geometry did not satisfy the policy-input premise. The prescribed gate stopped candidate creation and driving. The route/action propagation check was not reached, and no claim of unchanged candidate actions or treatment efficacy is made. The active baseline, historical candidates and outcomes remain preserved.

Passing this first gate would still require a separately frozen candidate to change the actual selected path and action on saved inputs, while every newly selected connector meets the same policy hazard constraint. Returning an unchecked original route and declaring a fallback does not establish that condition. A no-route braking intervention has different semantics from the historical route fallback and must be named accurately. This audit provides no new completion, progress, contact, safety or causal-effect evidence; private case identities, traces, action indices and numeric diagnostics stay outside the repository.
