## 정적 profile 검사와 중단 이유

2×2가 N1 하나를 대상으로 하므로 기존 N1 pace1.0 profile만 검사했다. 새 envelope를 생성하거나 최적화하지 않았다. 원래258의 곡률·100m/s 상한 C, `A_i=min(rear traction,80000/(v_i+2.7)/effective_mass)`, 고정 B와 저장 구간 길이에 대해 다음을 float64로 평가했다. [정적 검사 코드](profile400_audit.py)

```
W_i = v_i²
-W_i <= 0
W_i-C_i <= 0
W_(i+1)-W_i-2*A_i*ds_i <= 0
W_i-W_(i+1)-2*B*ds_i <= 0
W_0=0, W_N>0, 모든 값 유한, ds_i>0
```

| 검사 | 양의 잔차 수 | 최대 양의 잔차 m²/s² |
|---|---:|---:|
| 비음성 |0 |없음 |
| C 상한 |0 |없음 |
| 전방 drive |72 |1.336×10⁻¹² |
| 후방 brake |14 |2.274×10⁻¹² |

출발0·양의 종단·유한성·양의 구간 길이는 통과했다. 원래 planner는 `sqrt(W+2*A*ds)` 형태로 속도를 반복 제한하므로, 저장된 속도를 다시 제곱해 엄격한0 잔차를 요구하면 반올림 크기의 초과가 생길 수 있다. 관측 잔차의 규모는 그 설명과 부합한다. **큰 동역학 제약 위반을 새로 발견한 것은 아니다.** 그렇더라도 등록된 판정에는 허용오차가 없었으므로 미자격을 숨기거나 결과를 본 뒤 tolerance를 넣지 않았다. 정적 CPU0.00129초·wall0.00130초·적분0이었다.

source 보장 감속 B나 등분 횡력 가정의 정당성을 이 검사로 확보한 것도 아니다. pace1.0은 계속 원래 근사 모델의 가설 후보이며, 이 단계에서 source-feasible envelope로 승격되지 않는다. 이번 중단으로 두 설명의2×2 효과나 공동 실행의 추가 이득은 **미확인**이다. 398의 두 안전 중단과 과거265/268/269 실제 결과는 그대로다. 296 승격이나11초 목표의 가능/불가능 결론은 없다.

다음에 진행하려면 먼저 수치 자격 방법을 별도 사전 등록해야 한다. 예컨대 sqrt 기반 제약의 반올림 오차를 명시적으로 다루는 구간 산술·방향 반올림 인증과 실제 저장 profile의 물리적 margin을 분리해 검사할 수 있다. 그런 검사가 통과해도 분기 복원·상태 독립성 자격은 여전히 필요하다. **이번 작업에서는 허용오차 변경·profile 수리·추가 모델 전이·후속 실행을 하지 않았다.**
