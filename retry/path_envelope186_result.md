186 — 경로를 자르는 lookahead 목표의 기하 검사와 목표점 선택 한 후보

**초기 접촉은 늦췄지만 완주 수를 늘리지 못했다.** 기존 완주는 모두 유지했다. oracle 완주 도로는 1.26초 느려졌고, 합법 픽셀 clean DEV 한 개는 0.34초 빨라졌으나 damage가 늘었다. 현재 챔피언을 유지하며 추가 탐색 없이 닫는다.

저장된 185의 같은 52번 입력에서 선택 경로·기존 목표 추종 호·실제 궤적을 같은 차체 좌표계로 비교했다. 실제 기록된 curvature와 경로의 유일한 교점으로 원래 목표를 복원했으며 정답 속도로 lookahead를 대체하지 않았다. 목표의 경로상 거리는 **12.331m**, 단순 호 길이는 **11.647m**, 호 중심의 경로 이탈은 최대 **1.081m**였다. 전체 차체의 장애물 여유 하한은 경로에서 **+0.02997m**, 호에서는 **−0.67652m**였다. 음의 하한은 충돌 증명이 아니지만 경로가 가진 보수적 여유를 호가 잃는 것을 보인다.

동일한 출발 상태에서 적용 조향을 고정한 단순 호의 실제 형상 기반 표본 간격은 좌측 **0.02997m**, 원래 **0.96472m**, 우측 **1.74451m**였다. 위험 순서 좌측 > 원래 > 우측은 185 결과와 일치하며 표본화 오차보다 차이가 크다. 그러나 단순 호의 표본 간격은 모두 양수인 반면 실제 좌측·원래 행동은 접촉했다. 좌측의 보수적 하한은 표본화 오차 범위 안이다. 따라서 이 호를 검증된 dynamics나 충돌 예측 모델로 주장하지 않는다. 실제 대조는 4회 pulse 뒤 폐루프였고 비교한 호는 일정 곡률을 고정한 기하 계산이다.

현재 ZIP의 목표 선택은 속도에 따른 6~14m 경로 길이만 사용한다. 저장소의 비활성 `chord_agent`는 직선 현과 2.6m 팽창 반경을 검사하며, 이번 호·경로 이탈 검사와 같지 않다. 과거 실험을 재개하지 않았다.

후보는 최종 목표점 선택만 바꿨다. 현재 목표를 먼저 검사하고, 실패하면 그 앞의 기존 경로 꼭짓점을 먼 순서로 검사한다. 호 표본 A를 목표까지의 경로 전체에 투영한 Q에 대해 다음을 만족하는 첫 점을 고른다.

`min_j(||Q−C_j||−r_j) − R_vehicle − ||A−Q|| ≥ 표본 간 호 길이 / 2`

`R_vehicle=2.873564m`는 공식 hull·바퀴를 감싸는 반경과 skin에서 얻었다. 호 표본 간격은 0.05m 이하이며 반 간격 항은 연속 구간을 덮는 수치 오차 항이다. 임계값 sweep은 없다. 만족하는 점이 없으면 원래 목표를 유지하고, 별도 제동·조향 이득·인식·경로 유지 상태를 넣지 않았다. 52번 저장 입력에서는 목표 경로 거리가 **12.331→9.406m**, 검사 여유가 **−0.75679→+0.21143m**로 바뀌었다. 좌우 반사 입력에서 목표도 반사되는 검사를 통과했으며 고정 방향·고정 진폭 pulse를 정책으로 옮기지 않았다.

원본 ZIP 14개 파일 중 `schedule_agent.py`의 최종 목표 import·호출만 바꾸고 helper 하나를 추가했다. 나머지 13개와 경로 선택 점수용 원래 `route_target`은 그대로다. 기존 조향·페달 수식도 유지했다. 목표 변경은 기존 곡률 기반 속도 목표와 이후 폐루프 상태를 바꿀 수 있으므로 조향만의 효과로 해석하지 않는다.

oracle 공통 완주 차이는 `[+1260ms]`, 합계·평균·중앙값 모두 **+1260ms**다. 합법 픽셀은 `[−340ms]`, 합계·평균·중앙값 모두 **−340ms**다. 두 정보 조건을 합쳐 일반 개선으로 주장하지 않는다. 완주는 oracle **1/2→1/2**, 합법 픽셀 **1/1→1/1**이며 새 완주는 없다. damage는 별도 진단이고 자동 탈락 기준으로 쓰지 않았다.

실패 oracle 도로의 최초 접촉은 **62번·4.96초→다른 장애물의 255번·20.40초**로 바뀌었다. 그러나 260번에 crash했고 진행량은 35 tiles 줄었다. 초기 회피의 국소 개선이 전체 완주 개선을 보장하지 않았다. 합법 clean DEV의 새 접촉은 245번·19.60초였다.

실제 목표 변경은 순서대로 **31·17·29회**, 최초 변경은 **42·51·53번**이었다. 유효한 짧은 목표가 없어 원래 목표로 돌아간 호출은 **31·17·27회**였다. 따라서 이 후보는 전체 주행의 안전 보증이 아니다. 원래 경로 점수 함수 바인딩, 선택 목표, 기존 32 또는 24 / near8 / cap45와 P 법칙, 초기 상태·스트림 hash·actor 회수를 확인했다. 정적 정책 인터페이스 검사는 reset 2회·act 2회였으며 별도 native는 없다. 준비 중 fresh DEV 초기 캐시 참조 누락은 같은 기준 결과의 초기 상태로 복구했고 재실행 비용은 없다.

새 native **1,121/5,000회**, raw step **4,482틱**, reset **153틱**이다. 같은 정보 기준선 1,161회분은 저장 결과를 재사용했다. 실행 wall **70.559초**, evaluator CPU **61.120초**, actor CPU **12.612초**이며 저장 기하·준비·정적 검사·게시는 제외했다. **B800,000 = 누적709,320 + 연구6,680 + 예비84,000(사용0)**.

선행 기하 가정은 국소적으로 지지됐지만 이번 한 후보의 일반적인 완주·시간 개선은 입증되지 않았다. 추가 threshold·모델 확대·native 실행을 하지 않는다. 새 HOLDOUT·SEALED를 닫고 챔피언·main·Participants·기존 백업을 보존했다. 정렬된 좌표·궤적·전체 기록은 비공개로 유지했다.
