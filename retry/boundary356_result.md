# 356 지원점 제외 반례의 원인과 영향

**92에서 제외된 것은 그 입력의 새 직접 검출(age 0)이다.** 과거 미지원 lineage가 나중에 현재 지지를 얻은 경우가 아니다. 좌표·시점 대응 오류도 발견되지 않았다. 고정 규칙의 1픽셀 raw-road 링이 화면 경계의 현재 직접 성분을 low로 판정한 사례다.

| 행동 | 출생 age | raw-road 이웃 | routing 제외 | fixture 2 중심 거리 |
|---|---:|---:|---|---:|
| 91 | 0 | 3 | 아니오 | 0.283m |
| 92 | 0 | 0 | 예 | 0.360m |
| 93 | 0 | 3 | 아니오 | 0.325m |

세 출생 모두 같은 fixture 반경 1.200m 안에 있고, 성분 픽셀 중심도 소스 카메라로 투영한 fixture 영역 안에 있다. 91→92와 92→93은 각각 약 0.091m·0.082m의 원래 2m dedup 교체다. 오래된 점을 유지한 것이 아니라 매번 새 직접 검출이 이전 점을 대체한다. 92의 다른 age 7 점은 제외 대상이 아니었다. UID 92:0은 **92 한 번만 제외되고 93에서 교체**된다.

출생 시점과 제외 시점은 모두 92이므로 지원 근거도 같은 입력·같은 preaction fixture다. 원래 보존 게이트의 retained 절은 출생 당시의 지원 라벨을 이어 쓰며, 현재 가까워진 물체에 사후 재할당하는 방식이 아니다. 이번 사례는 그 모호함 없이 **supported direct birth** 절을 위반한다.

확인한 좌표·시점 근거는 다음과 같다.

- 저장 입력 hash가 실제 actor의 현재 이미지 hash와 일치하고, 92의 prephysics는 91의 postphysics와 같다.
- detector의 현재 성분 중심→metric→픽셀 왕복이 일치하며, age 0 위치는 affine/fallback으로 예측된 과거 점이 아니다.
- renderer의 카메라·flip·두 단계 resize에 따른 픽셀 중심 투영을 별도로 계산해 기존 GT 대응식과 일치했다. 대응 fixture는 하나뿐이다.

따라서 **현재 직접 검출이고 실제 fixture 2와 기하학적으로 대응한다는 근거는 강하다.** 다만 저장된 RGB/재질 정답 마스크가 없어 영상의 의미론적 재질이나 실제 가림까지 확정한 것은 아니다.

성분은 화면 왼쪽에 잘려 있고 92의 면적은 4픽셀이다. 보이는 1픽셀 링은 8개 샘플이며 추가 4개 위치는 화면 밖이라 관측되지 않는다. 보이는 링의 회색값도 모두 raw-road 밝기 범위보다 높아 이웃 수가 0이 됐다. 더 바깥에는 도로 픽셀이 있다. 즉 **관측되지 않는 경계와 중간 밝기 halo를 “장애물이 아님”의 근거로 쓸 수 없다.** resize/antialias에 따른 혼합은 소스 파이프라인과 부합하지만 새 렌더링으로 재현한 재질 정답은 아니다.

영향 확인은 92의 저장 입력 한 개에만 고정했다. 실제 filtered 경로·목표를 정확히 재현한 다음, 해당 footprint 하나만 복원했다. **경로와 목표점은 정확히 같았다.** 전체 hazards·near/count/min-distance·사전 controller 상태·속도·이전 조향은 고정했다. 경로 길이·점 개수·목표도 같은 만큼 동결된 결정적 nominal/controller·pedal head·H1 입력이 같다. 따라서 **92의 조작·명목 기억 차이는 없다는 소스 의존성 추론**이 성립한다. 실제 기록의 특징·audit·기억 연결도 대조했다. 새 controller/actor를 실행한 반사실 측정이나 새 폐루프 lap·접촉 비교는 아니다.

기존 게이트는 [공개된 등록 코드](support342_stage.py#L64)의 다음 문장이다.

> Any fixture-supported direct or birth-supported retained point withheld, any reproduction/integrity failure: stop, no candidate pass.

[평가 코드](support342_run.py#L55)는 지원되는 low 직접 출생과 제외된 UID의 출생 지원 라벨을 검사한다. 원래 규칙에서는 low 직접 출생이 곧 routing 제외이므로 두 검사가 같은 UID를 잡을 수 있다. **이번 손실은 제외 footprint 하나이며 두 개의 독립 손실로 세지 않는다.** tracker 전체에서 지운 것은 아니지만 hard routing에서 제외했으므로 위 게이트는 실패한다. 경로·제어가 같아도 이 무조건적 보존 요구를 사후 완화하지 않는다. GT 라벨은 사후 진단이며 실행 정책의 선택 입력이 아니다.

가장 작은 수정 **가설**은 routing 선택 한 곳만 바꾸는 것이다.

> low 출생 플래그가 있어도 현재 직접 검출(age 0)은 routing에 보존하고, age > 0인 retained 점만 제외 후보로 삼는다.

새 threshold·학습·GT 입력 없이 기존의 직접/retained 구분만 사용한다. detector·출생 플래그·추적·dedup·expiry·전체 hazards 특징·H1·제어기는 유지한다. **아직 적용·패키징·shadow 실행하지 않았다.** 92는 보존되고 알려진 N2의 중요한 127–129 retained 점(age 6–8)은 제외 후보로 남는다는 예측이다. 이는 검증 전 예측이며, 실제 지원 출생이 재검출 없이 유지되면 나중에 제외될 위험은 여전히 있다. 따라서 완전한 안전 수정이라고 부르지 않는다.

제안 검증 계약은 다음 순서다.

1. 별도 비공개 variant를 한 선택 변경으로만 동결한다. 기존 342+355 자료에서 실제 routing UID 포함 여부로 직접·출생 지원 retained 보존을 각각 감사한다. low 메타데이터와 실제 제외를 구분하되 기존 “지원점 제외 금지” 요구는 약화하지 않는다. retained 지원점 제외가 하나라도 있으면 중단한다.
2. 통과한 경우에만 T2954의 92와 N2의 121을 고정 함수로 비교한다. 두 자료 전체 상한은 routing 4회·target 4회, actor/controller/native 0이다. 이번 92 결과와 함수 hash·입력이 같으면 재사용해 중복 호출하지 않는다. N2 127–129 선택은 age/UID로 같음을 확인한다. 원본 재현 실패나 필요한 N2 효과 소실 시 threshold 조정 없이 중단한다.
3. 그 뒤에도 별도 기억·폐루프 불확실성이 남을 때만 새 계약을 만든다. 이번 작업은 새 주행을 승인하거나 예약하지 않는다.

이번 비용은 **직접 routing 2회·target 2회**, actor/controller/native/학습/후보 수정 0회다. 함수 내부의 후보별 target 계산은 routing 연산에 포함하며 별도 직접 호출로 세지 않았다. 주 감사 벽시계 0.589초·CPU 0.389초, 격리 함수 0.025초·CPU 0.032초였고 후속 특징 확인·문서화·git 전체 시간은 제외한다. 연구 **1,644회**, 예비 **84,000회**를 보존했다.

원본 영상·crop·pose/GT·seed·모델·개인 문서는 비공개 위치에만 보관했다. 공개 결과에는 집계된 근거·일반 코드·공개 게이트만 포함한다. 후보 349·champion 296·main·Participants·기존 변경·백업을 보존했으며 새 split 개봉·승격은 없다.
